# 🧠 AI NLP — YandexGPT и эмбеддинги поверх ядра и выдачи

Четыре задачи на Yandex Foundation Models. Результаты — в отдельной схеме `ai`
([schema.sql](schema.sql)); существующие таблицы (`common.*`, `yandex.*`) не меняются.

| # | Задача | Скрипт | Куда пишет |
|---|---|---|---|
| 1 | Классификация ядра: интент, продукт, стадия воронки | `npm run ai:classify` | `ai.request_intent` |
| 2 | Эмбеддинги запросов | `npm run ai:embed` | `ai.request_embeddings` |
| 3 | Кластеризация по выдаче + довешивание по эмбеддингам + названия | `npm run ai:cluster` | `ai.clusters`, `ai.cluster_members` |
| 4 | Разбор title/snippet конкурентов, сводки по кластерам | `npm run ai:snippets` | `ai.snippet_analysis`, `ai.cluster_competitor_summary` |

Журнал запусков, токены и оценка стоимости — `ai.runs`.

## Настройка

В `.env` (см. `.env.example`):

```
YANDEX_AI_API_KEY=...      # API-ключ сервисного аккаунта с правом вызывать Foundation Models
YANDEX_AI_FOLDER_ID=...    # необязательно: по умолчанию берётся YANDEX_SEARCH_FOLDER_ID
```

Ключ Search API для этого не подходит: нужен ключ сервисного аккаунта с ролью на
языковые модели (`ai.languageModels.user`) и областью действия Foundation Models.
Точные названия роли и области проверь в консоли Yandex Cloud.

## Порядок запуска

1. `npm run ai:classify -- --dry-run` → смотрим оценку, потом `npm run ai:classify`
2. `npm run ai:embed -- --dry-run` → `npm run ai:embed`
3. Нужны данные `yandex.serp_results` (прогон `yandex-serp`). Сначала
   `npm run ai:cluster -- --dry-run` (кластеры в консоль, БД не трогаем), потом без флага.
4. `npm run ai:snippets -- --dry-run` → `npm run ai:snippets`, затем
   `npm run ai:snippets -- --summaries` (сводки нужны кластеры и разбор сниппетов).

Общие флаги: `--dry-run` (оценка стоимости, API не вызывается), `--limit N`,
`--model pro` (YandexGPT Pro вместо Lite). Все скрипты идемпотентны — повторный
запуск обрабатывает только то, чего ещё нет (`--force` у классификации перезаписывает).

## 💰 Деньги

Тарифы в [config.json](config.json) → `pricesRubPer1kTokens` — **ориентировочные**, сверь с
прайсом. Оценка в `ai.runs.est_cost_rub` считается по ним, это не данные биллинга.
Токены считаются по ответу API, в `--dry-run` — грубо (~2,5 символа на токен).

`maxCostRubPerRun` (по умолчанию 150 ₽) — потолок на один запуск: при превышении
оценки скрипт останавливается, уже записанное остаётся.

## Как работает кластеризация

- Для каждого запроса берётся последний снимок выдачи (за `serpWindowDays`, топ-`topN`).
- Голова кластера — самый частотный запрос (Wordstat за последний месяц, затем показы GSC).
  Все запросы, у которых с головой ≥ `minSharedUrls` общих URL, входят в кластер.
  Сравнение именно с головой, а не цепочкой — кластеры не «расползаются».
- Запросы без выдачи, но с эмбеддингом, присоединяются к ближайшему кластеру, если косинус
  к центроиду ≥ `assignThreshold` (`assigned_by = 'embedding'`).
- Пороги — стартовые; смотри результат через `--dry-run` и подбирай `--min-shared`.
- Запросы из `yandex.serp_results`, которых нет в `common.requests` (джойн по тексту),
  пропускаются.

## Вью

- `ai.v_request_clusters` — запросы с кластерами последнего успешного запуска
- `ai.v_request_classified` — запросы + интент/продукт/стадия
- `ai.v_competitor_offers` — выдача + офферы, цены, триал, SLA, 24/7 по доменам

## Ограничения

- `confidence` — самооценка модели, не вероятность; выборочно проверяй разметку глазами.
- Разбор сниппетов видит только то, что Яндекс показал в title/snippet, а не весь текст страницы.
- Эмбеддинги — массивы `double precision[]`, косинус считается в Node. Для тысяч запросов
  это нормально; при десятках тысяч стоит поставить pgvector.
- Тесты чистой логики (без БД и API): `node tests/test-ai-nlp.js`.
